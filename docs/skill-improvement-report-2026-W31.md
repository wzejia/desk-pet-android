## 高频模式（≥3 次）

### P1 用户拍板翻案/改判（≥6 次：#2 #5 #15 #23 #25 #28 #29)
契约或上午裁决下午翻（导航改判/多会话推翻 R2/盲测尺子改判/双窗口职责翻转/同日两翻）。
根因=需求信息分阶段补全，非执行失误。**好例对照**:#3 悬浮窗参照物 adb 实证先行，
该决策零翻案。
→ 改进：拍板记录带「可推翻条件」;brainstorm 阶段参照物实测前置。

### P2 守卫窗/异步竞态反复出现（≥7 次：#26 #31-33 #36-39)
全部集中在 voice/异步管线域：功能路径先行，守卫（开窗/关窗配对、异常终态、取消语义、
重复触发）靠 critic 打回补——每次都中，说明是**票据结构性缺口**而非 builder 水平问题。
→ 改进：异步管线票派单模板前置「守卫四问」。

### P3 代码层过 ≠ 真机语义过（3 次：#42 一轮、抽屉双失灵、B3 虚警)
#42 窗 margin clamp 代码正确但精灵不可见（像素 43 实证）;「组件默认行为」 backlog 假设
真机一测即穿;B3 靠三连截图才定案非 bug。
→ 改进：可见性/可听性类验收必须像素/物理断言;critic 派单标注「语义验收型」;
「组件默认应该有」一律降级为待真机断言。

### P4 builder 自报失实被 critic 抓（3 次：#33 背景、#37、#42 估 84px)
虚报 notes 已记/「同形态」措辞失准/可见像素数估值与实测不符。
→ 改进：返回三样增补「数字必附命令原文或推导，估值标估」。
